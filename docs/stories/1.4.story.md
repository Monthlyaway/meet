# Story 1.4: Gaming Room Creation and Management

## Status

## Story
**As a** authenticated gaming user,
**I want** to create gaming chat rooms with unique access tokens,
**so that** I can organize voice chat sessions for my gaming team.

## Acceptance Criteria

1. Room creation API generates unique access tokens and stores room metadata
2. Room creation UI integrated into existing Next.js frontend
3. Room creator is automatically assigned as administrator
4. Room list API allows users to see their created and joined rooms
5. Access token sharing interface for room distribution
6. Room deletion functionality for administrators

**Integration Verification:**
- **IV1**: Existing LiveKit Meet room creation continues to work independently
- **IV2**: Current room joining by name/URL remains functional alongside token-based joining
- **IV3**: LiveKit room management integration works correctly with new backend room metadata

**Data Models**: [Source: architecture/data-models.md]
Required TypeScript interfaces:
```typescript
interface Room {
  id: number;
  name: string;
  accessToken: string;
  creatorId: number;
  createdAt: string;
  isActive: boolean;
  creator?: User;
  channels?: Channel[];
  members?: User[];
}

interface RoomCreation {
  name: string;
}

interface Channel {
  id: number;
  name: string;
  roomId: number;
  isMainLobby: boolean;
  livekitRoomName: string;
  createdAt: string;
}
```

**Database Schema**: [Source: architecture/database-schema.md]
- `rooms` table: id, name, access_token (UUID), creator_id, is_active, created_at
- `channels` table: id, name, room_id, is_main_lobby, livekit_room_name, created_at
- `room_members` table: id, user_id, room_id, joined_at, is_active
- Foreign key constraints: rooms.creator_id → users.id, channels.room_id → rooms.id

**API Specifications**: [Source: architecture/rest-api-spec.md]
- `POST /api/rooms` - Create room with JWT auth, returns {room, accessToken}
- `GET /api/rooms` - List user's rooms (created and joined)
- `DELETE /api/rooms/{id}` - Delete room (creator only)
- All endpoints use Bearer JWT authentication
- Response format: JSON with proper error handling

**Core Workflows**: [Source: architecture/core-workflows.md]
Room Creation Flow:
1. User fills room creation form → Frontend validates input
2. Frontend → `POST /api/rooms` with JWT → Backend validates JWT
3. Backend generates UUID token → Creates room record → Creates main lobby channel
4. Backend → LiveKit server creates room for main lobby
5. Backend returns {room, accessToken} → Frontend displays token for sharing

**Components Specification**: [Source: architecture/components.md]

- `/rooms` - Room list with admin controls and token sharing
- `useRoom()` - React hook for current room state and operations
- Integration with existing `useAuth()` hook for user context
