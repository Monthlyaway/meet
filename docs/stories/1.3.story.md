## Story
**As a** user sharing room links,
**I want** URLs to follow `/rooms/{roomId}/channels/{channelId}` pattern and seamlessly switch between channels,
**so that** I can share specific channels with others and maintain context while navigating between discussions.

## Acceptance Criteria
1. URL structure follows `/rooms/{roomId}/channels/{channelId}` pattern
2. Clicking channel name switches to new LiveKit room connection
3. Sidebar remains visible during channel switches
4. New room joins automatically go to "Main Lobby"
5. URL sharing works for specific channels
6. Browser back/forward navigation works correctly
7. Clean user flow with `npm run dev` producing useable frontend with no errors
8. Users can share `/rooms/{roomId}` URLs which redirect to main lobby channel

### Route Handler Implementation Pattern
[Source: team-channels-epic.md routing specifications]

**New Route Structure to Implement:**
```typescript
// app/rooms/[roomId]/channels/[channelId]/page.tsx
export default async function ChannelPage({
  params,
  searchParams,
}: {
  params: Promise<{ roomId: string; channelId: string }>;
  searchParams: Promise<{ region?: string; hq?: string; codec?: string }>;
}) {
  const { roomId, channelId } = await params;
  const _searchParams = await searchParams;

  // Validate room exists
  const metadata = await getRoomMetadata(roomId);
  if (!metadata) {
    notFound(); // 404 page
  }

  // Validate channel exists, redirect to main-lobby if not
  const channels = await getChannels(roomId);
  const channel = channels.find(c => c.channelId === channelId);
  if (!channel) {
    redirect(`/rooms/${roomId}/channels/main-lobby`);
  }

  // Handle codec and quality parameters (preserve existing logic)
  const codec = isValidCodec(_searchParams.codec) ? _searchParams.codec : 'vp9';
  const hq = _searchParams.hq === 'true';

  return (
    <ChannelWrapper roomId={roomId} currentChannel={channel} initialChannels={channels}>
      <PageClientImpl
        roomName={channel.livekitRoomName} // Use LiveKit room mapping
        region={_searchParams.region}
        hq={hq}
        codec={codec}
      />
    </ChannelWrapper>
  );
}
```

**Solution Implemented:**
1. **Server-Side Separation**: Created `lib/room-storage-server.ts` for server-only operations
2. **Client-Side Abstraction**: Created `lib/admin-identity.ts` for browser-based logic only
3. **Type System Unification**: Added shared interfaces to `lib/types.ts` for consistent typing
4. **Import Cleanup**: Updated all client components to use proper client-side imports

**Architecture Now Follows Next.js Best Practices:**
- Server components: Use `room-storage-server.ts` with direct file system access
- Client components: Use `admin-identity.ts` with fetch calls to API routes
- API routes: Handle all file system operations server-side
- Shared types: Consistent interfaces across client/server boundary
